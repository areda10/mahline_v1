# BROWSER_TRACKING_STANDARD.md

## MAHLINE Framework V1

**Version:** 1.0
**Status:** Frozen
**Domain:** Identity

---

# 1. Purpose

This document defines the official Browser Tracking standard for the MAHLINE Framework.

Its objectives are to:

* identify the client environment used during authentication;
* improve account security;
* detect suspicious login activity;
* support session management;
* provide authentication traceability.

Browser Tracking is a security feature and must never be used for advertising or user profiling.

---

# 2. Scope

Browser Tracking is used by:

* Authentication
* User Sessions
* Login History
* Security Monitoring
* Audit

It does not replace Laravel session management.

---

# 3. Tracking Strategy

Browser information is collected during every authentication event.

The collected information is stored as metadata and is never considered proof of user identity.

---

# 4. Browser Information

The following information should be recorded whenever it can be determined reliably:

* browser name
* browser version
* browser engine (optional)

Examples:

* Chrome
* Firefox
* Safari
* Edge
* Opera

---

# 5. Operating System

The operating system should be recorded.

Examples:

* Windows
* macOS
* Linux
* Android
* iOS

Optional:

* operating system version

---

# 6. Device Information

The framework should identify the device category.

Supported values:

* Desktop
* Laptop
* Tablet
* Mobile
* Bot
* Unknown

Additional metadata may be stored when available.

---

# 7. Platform Information

Examples:

* Windows x64
* Android ARM64
* macOS Apple Silicon
* Linux x86_64

Platform information is optional.

---

# 8. User Agent

The complete HTTP User-Agent string may be stored.

Requirements:

* preserve the original value;
* never modify the original string;
* use only for diagnostics and security.

---

# 9. IP Address

Browser tracking may include:

* IPv4
* IPv6

Optional:

* country
* ASN
* geolocation

These enrichments remain configurable and are not required by the framework.

---

# 10. Browser Fingerprinting

The framework **does not** rely on browser fingerprinting for authentication.

Browser metadata is used only as contextual security information.

No persistent browser fingerprint shall be generated by the framework.

---

# 11. Duplicate Browser Detection

The Identity domain may compare browser metadata to detect concurrent logins.

Supported policies include:

* allow concurrent logins;
* revoke previous session;
* reject the new login;
* administrator-defined policy.

Browser information alone must never be considered a unique identifier.

---

# 12. Session Integration

Every active session should reference browser metadata captured at login.

Changes detected during the session may be recorded according to the active security policy.

---

# 13. Login History Integration

Every authentication event records the browser metadata available at that moment.

Historical records must remain immutable.

---

# 14. Audit Integration

Security-sensitive browser events may be audited.

Examples:

* login from a new browser;
* browser change after authentication;
* forced session revocation due to policy.

---

# 15. Privacy

Browser metadata is collected exclusively for security purposes.

The framework must:

* minimize collected data;
* avoid unnecessary personal information;
* comply with applicable privacy regulations.

---

# 16. Foundation Responsibilities

The Foundation provides:

* reusable abstractions;
* browser parsing integration points;
* common value objects and helpers.

The Foundation does not define security policies.

---

# 17. Identity Responsibilities

The Identity domain manages:

* browser tracking;
* browser comparison;
* concurrent browser policies;
* browser-based security decisions;
* storage of browser metadata.

---

# 18. Development Rules

Every browser-tracking component must:

* use strict types;
* follow PSR-12;
* be testable;
* avoid hard-coded browser logic;
* support future parser replacements.

---

# 19. Best Practices

Recommended practices:

* treat browser information as advisory, not authoritative;
* combine browser data with session and IP information;
* never authenticate solely based on browser metadata;
* make browser policies configurable.

---

# 20. Checklist

Browser Tracking implementation must support:

* Browser name
* Browser version
* Operating system
* Device type
* Platform
* User-Agent
* IP address
* Session integration
* Login History integration
* Audit integration
* Configurable security policies
* Automated tests
