# 1. Purpose

This document defines the official specification for the `ColumnMacros` component of the MAHLINE Framework.

`ColumnMacros` extends Laravel's `Blueprint` by registering reusable macros that standardize column creation across all database migrations.

Its objectives are to:

* eliminate duplicated migration code;
* enforce MAHLINE database standards;
* improve migration readability;
* centralize common column definitions;
* ensure consistency across all domains.

---


Namespace:

```php
App\Core\Database\Macros
```

---

# 3. Responsibilities

`ColumnMacros` is responsible for registering reusable Blueprint macros related to database columns.

It must **not**:

* register audit macros;
* register foreign key macros;
* register index macros;
* contain business logic.

---

# 4. Dependencies

Required:

* Illuminate\Database\Schema\Blueprint

Optional:

* Framework configuration
* Future helper classes

No domain dependency is allowed.

---

# 5. Registration

The component exposes a single public entry point.

```php
public static function register(): void;
```

This method registers every column-related macro.

---

# 6. Official Macros

The following macros are part of MAHLINE V1.

## Primary Keys

```php
$table->ulidPrimary();
```

Creates:

* id
* ULID
* primary key

---

## Code Column

```php
$table->code();
```

Default:

* string(50)

Options may be added later.

---

## Slug Column

```php
$table->slug();
```

Default:

* string(255)

No index is automatically created.

---

## Status Column

```php
$table->status();
```

Default:

```text
active
```

Implementation details remain configurable.

---

## Locale Column

```php
$table->locale();
```

Default:

```text
config('app.locale')
```

---

## Timezone Column

```php
$table->timezone();
```

Default:

```text
UTC
```

---

## Phone Column

```php
$table->phone();
```

Default:

```text
string(30)
```

---

## Currency Column

```php
$table->currency();
```

Default:

```text
string(3)
```

ISO-4217 compatible.

---

## Country Column

```php
$table->country();
```

Default:

```text
string(2)
```

ISO-3166-1 alpha-2 compatible.

---

## UUID Primary (Optional)

```php
$table->uuidPrimary();
```

Provided for interoperability projects.

MAHLINE uses ULID by default.

---

# 7. Naming Rules

Every macro must use:

* singular names;
* descriptive names;
* consistent naming.

Examples:

```php
$table->locale();
$table->timezone();
$table->currency();
$table->status();
$table->phone();
```

Avoid abbreviations.

---

# 8. Return Type

Every macro must return the created Blueprint column definition to allow method chaining when supported by Laravel.

---

# 9. Design Rules

Macros must:

* use strict types;
* be framework-wide reusable;
* be deterministic;
* avoid side effects;
* avoid hidden indexes;
* avoid hidden foreign keys.

---

# 10. Performance

Macros should only register once during application boot.

Duplicate registration must be avoided.

---

# 11. Future Extensions

New macros must preserve backward compatibility.

# 14. Usage Example

```php
Schema::create('users', function (Blueprint $table) {
    $table->ulidPrimary();

    $table->status();

    $table->locale();

    $table->timezone();

    $table->phone();
});
```

---

# 15. Best Practices

* Prefer macros over duplicated column definitions.
* Keep each macro focused on one responsibility.
* Never embed business rules inside macros.
* Maintain backward compatibility.
* Use macros consistently across every migration.
