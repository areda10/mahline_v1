# 1. Purpose

This document defines the official specification for the `AuditMacros` component of the MAHLINE Framework.

`AuditMacros` extends Laravel's `Blueprint` by registering reusable macros that standardize audit-related columns across all database migrations.

Its objectives are to:

* eliminate duplicated audit column definitions;
* enforce MAHLINE audit standards;
* ensure consistency across all database tables;
* centralize audit column creation;
* improve migration readability.

# 3. Responsibilities

`AuditMacros` is responsible for registering audit-related Blueprint macros.

It must **not**:

* register generic column macros;
* register foreign key macros;
* register index macros;
* contain business logic.

---

# 4. Dependencies

Required:

* Illuminate\Database\Schema\Blueprint

Optional:

* ForeignKeyAction enum
* MigrationHelper
* Framework configuration

No domain dependency is allowed.

---

# 5. Registration

The component exposes one public entry point:

```php
public static function register(): void;
```

This method registers every audit-related macro.

---

# 6. Official Macros

## Audit Columns

```php
$table->auditColumns();
```

Creates:

* created_by
* updated_by
* deleted_by

All columns are:

* ULID
* nullable
* indexed

Foreign keys are **not** created automatically.

---

## Audit Timestamps

```php
$table->auditTimestamps();
```

Equivalent to:

```php
$table->timestamps();
```

Creates:

* created_at
* updated_at

---

## Complete Audit

```php
$table->auditable();
```

Creates:

* created_by
* updated_by
* deleted_by
* created_at
* updated_at

This macro does **not** create `deleted_at`.

Soft deletes are handled separately.

---

# 7. Generated Columns

| Column     | Type      | Nullable | Indexed |
| ---------- | --------- | -------- | ------- |
| created_by | ULID      | Yes      | Yes     |
| updated_by | ULID      | Yes      | Yes     |
| deleted_by | ULID      | Yes      | Yes     |
| created_at | timestamp | No       | No      |
| updated_at | timestamp | No       | No      |

---

# 8. Design Rules

Audit macros must:

* use ULID references;
* remain framework-wide reusable;
* avoid hidden foreign keys;
* avoid side effects;
* never include business rules.

---

# 9. Foreign Keys

Audit macros only create columns.

Foreign key constraints are handled by `ForeignKeyMacros`.

This separation follows the Single Responsibility Principle.

---

# 10. Return Type

Every macro returns the appropriate Blueprint definition to allow method chaining where supported.

---

# 11. Performance

Macros must:

* register only once;
* avoid duplicate registration;
* introduce no runtime overhead after boot.

---

# 12. Future Extensions

Possible future additions:

* created_from_ip
* updated_from_ip
* created_from_device
* updated_from_device
* created_from_browser
* updated_from_browser

These extensions are intentionally excluded from MAHLINE V1.

Documentation must include:

---

# 15. Usage Example

```php
Schema::create('products', function (Blueprint $table) {
    $table->ulidPrimary();

    $table->auditable();
});
```

---

# 16. Best Practices

* Use `auditable()` for most business tables.
* Keep audit concerns separate from foreign keys.
* Do not duplicate audit columns manually.
* Always follow MAHLINE audit standards.
